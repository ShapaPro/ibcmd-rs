# Команды ibcmd-rs

Справочник по всем командам версии 0.3. Проект в стадии активной доработки:
рабочим для повседневного использования он станет к версии 1.0, ход работ —
в [майлстоунах](https://github.com/Untru/ibcmd-rs/milestones). Команды,
которые пишут в базу, запускайте только на копиях баз.

Утилитой можно пользоваться двумя способами:

1. **[Синтаксис штатного `ibcmd`](#1-синтаксис-штатного-ibcmd)**:
   `ibcmd infobase config export|import`. Это основной способ: утилита
   подменяет `ibcmd.exe` для выгрузки и загрузки конфигурации.
2. **[Собственные команды `ibcmd-rs`](#3-основные-команды-ibcmd-rs)**: те же
   выгрузка и загрузка с подробными параметрами, сравнение выгрузок, а также
   [исследовательские команды](#4-остальные-команды).

Полный список параметров любой команды печатает сама утилита:
`ibcmd-rs <команда> --help` (у синтаксиса `ibcmd` справка на русском:
`ibcmd infobase --help`).

## 1. Синтаксис штатного `ibcmd`

Скопируйте `ibcmd-rs.exe` под именем `ibcmd.exe` в отдельную папку, и
выгрузка и загрузка конфигурации запускаются теми же командами, что у
штатного `ibcmd`. Штатный `ibcmd.exe` платформы не удаляйте: `config apply`
и `infobase create` выполняет он.

### Выгрузка конфигурации в XML

```
ibcmd infobase config export [параметры] <каталог>
```

Каталог должен быть пустым или отсутствовать, как у штатного `ibcmd`.

### Загрузка XML в базу

```
ibcmd infobase config import [параметры] <каталог>
```

Загрузка записывает конфигурацию в таблицу ConfigSave; применяет её
штатный `ibcmd infobase config apply`. Если в базе нет конфигурации этого
дерева (база только что создана `ibcmd infobase create`), каждая строка
собирается из XML, отдельного ключа не нужно.

Если конфигурация в базе уже есть, строки базы правятся по дереву, и не всё
из дерева такая правка переносит: имя, синоним и комментарий объектов,
модули, формы, макеты, права ролей и командные интерфейсы переносятся, а
реквизиты, табличные части, значения перечислений, свойства объектов, состав
подсистем и свойства конфигурации остаются как в базе. Чтобы такая загрузка
не теряла изменения молча, перед записью в ConfigSave утилита выгружает
моделью конфигурацию, какой она станет после загрузки, и сравнивает каждый
файл с деревом (XML по элементам, а не по пробелам; модули без учёта концов
строк). Расхождение отменяет загрузку: код возврата -1, в сообщении
перечислены файлы и что в них не совпало, ConfigSave остаётся таким, каким
был. Проверка добавляет к загрузке выгрузку конфигурации в памяти (БСП:
десятки секунд). `--no-verify` отключает её; `--verify` включает и для
загрузки, собранной из XML (для пустой базы по умолчанию выключена).

### Подключение к базе

| Параметр | Что задаёт |
|---|---|
| `--dbms=MSSQLServer` | Тип СУБД. Поддерживается только `MSSQLServer`. |
| `--db-server=<сервер>`, `--database-server` | Сервер: `server`, `server\instance`, `server/instance` (как пишет штатный `ibcmd`), `server,port`. По умолчанию — из настроек, иначе `localhost`. |
| `--db-name=<база>`, `--database-name` | Имя базы данных. |
| `--db-user=<логин>`, `--database-user` | Логин SQL Server. Без него — вход Windows. |
| `--db-pwd=<пароль>`, `--database-password` | Пароль логина SQL Server. |
| `-W`, `--request-db-pwd`, `--request-database-password` | Прочитать пароль из стандартного ввода (первая строка). |
| `-c <файл>`, `--config=<файл>` | Файл настроек штатного `ibcmd` (YAML, который пишет `ibcmd server config init`). Из его раздела `database:` берутся СУБД, сервер, база, логин и пароль, не заданные параметрами. |
| `--data=<каталог>`, `-d` | Каталог данных сервера; загрузка оставляет служебные файлы в его подкаталоге `temp`. |
| `--temp=<каталог>`, `-t` | Каталог временных файлов. |
| `--user`, `-u`, `--password`, `-P` | Пользователь информационной базы. Принимаются и не нужны: утилита работает с таблицами напрямую. |
| `--system`, `--lock`, `--users-data`, `--session-data` и другие `--*-data` | Принимаются для совместимости и не используются. |

Оба написания имён (`--db-server` и `--database-server`) и обе формы значения
(`--x=значение` и `--x значение`) равноправны.

**Вход SQL Server.** Без `--db-user` утилита входит от имени пользователя
Windows. Для логина SQL Server:

```
ibcmd infobase config export --dbms=MSSQLServer --db-server=sql01 ^
  --db-name=MyBase --db-user=sa --db-pwd=Secret C:\export\MyBase
```

Чтобы пароль не попадал в историю команд, вместо `--db-pwd` задайте его:
- переменной окружения `IBCMD_DB_PSW`;
- через стандартный ввод с `-W`: `echo Secret| ibcmd ... -W C:\export\MyBase`;
- в разделе `database:` файла `--config`.

Если логин указан, а пароля нет нигде, утилита отказывает с подсказкой.

### Параметры выгрузки

| Параметр | Что задаёт |
|---|---|
| `--threads=<n>`, `-T <n>` | Число потоков выгрузки: по умолчанию — число ядер, но не больше 16; явно — до 64. |
| `--force` | Принимается. Непустой каталог, как и у штатного `ibcmd`, не перезаписывается. |
| `--ignore-unresolved-refs` | Принимается для совместимости. |

### Параметры `ibcmd-rs` (у штатного `ibcmd` их нет)

| Параметр | Что задаёт |
|---|---|
| `--platform=<версия>` | Версия платформы базы: `8.3.27`, `8.5.1` или сборка (`8.3.27.2214`, `8.5.1.1150`). Задаёт формат XML, см. [раздел 2](#2-версия-платформы-настройки-и-переменные-окружения). |
| `--report=<файл>` | Записать подробный отчёт о выполнении в JSON. |
| `--sqlcmd=<путь>` | Работать через `sqlcmd.exe` и `bcp.exe`, как версия 0.2. По умолчанию утилита подключается к SQL Server сама. |
| `--settings=<файл>` | Файл настроек JSON с ключами vRunner (`dbms-server`, `dbms-base`, `dbms-user`, `dbms-pwd` и другие). |
| `--db-pwd-env=<имя>` | Переменная окружения с паролем SQL Server (по умолчанию `IBCMD_DB_PSW`). |
| `--base-free` | Загрузка: собрать все строки из XML, не читая конфигурацию базы. Обычно не нужен: для пустой базы режим выбирается сам. |
| `--verify`, `--no-verify` | Загрузка: сравнить с деревом конфигурацию, какой она станет, до записи в ConfigSave; расхождение отменяет загрузку (код -1). По умолчанию проверяется загрузка в базу с конфигурацией. Переменная `IBCMD_RS_STAGE_VERIFY=0\|1` делает то же для скриптов. |
| `--source-version=<2.20\|2.21>` | Прежнее указание формата XML; вместо него — `--platform`. |

### Что пока не поддерживается

Остальные команды и режимы штатного `ibcmd` разбираются и отвечают
сообщением «… не поддерживается в этой версии ibcmd-rs (планируется в
следующих)» с кодом 1; штатный `ibcmd` вместо них не запускается:

- режимы `server`, `eventlog`, `config`, `extension`, `mobile-app`,
  `mobile-client`, `session`, `lock`, `binary-data-storage`;
- команды `infobase create`, `dump`, `restore`, `clear`, `replicate`;
- `infobase config apply`, `check`, `load`, `save`, `reset`, `repair`,
  `support`, `data-separation`, `extension`, `generation-id`, `sign`;
- `infobase config export info|status|objects|all-extensions`,
  `infobase config import files|all-extensions`;
- параметры выгрузки `--base`, `--file`, `--extension`, `--sync`,
  `--archive`; загрузки `--out`, `--extension`; общие `--pid`, `--remote`;
- файловые базы (`--db-path`) и СУБД кроме `MSSQLServer`.

### Вывод и коды возврата

При успехе утилита печатает то же, что штатный `ibcmd`:

```
[INFO] Экспорт конфигурации в XML...
[INFO] Экспорт конфигурации в XML успешно завершен
```

При ошибке — строки `[ERROR] …` в stderr, последняя
`[ERROR] … завершен с ошибкой`.

| Код | Когда |
|---|---|
| 0 | успех |
| 2 | ошибка в командной строке: неизвестный параметр, нет значения, неполная команда, неизвестная СУБД (как у штатного) |
| −1 | операция завершилась с ошибкой (как у штатного; в bash видно как 255) |
| 1 | команда или параметр не поддерживаются в этой версии `ibcmd-rs` |

`ibcmd -v` (и `--version`) печатает версию утилиты, `ibcmd help` — список
режимов.

## 2. Версия платформы, настройки и переменные окружения

### Версия платформы

Версия платформы определяет формат XML:

| Платформа | Формат XML |
|---|---|
| `8.3.27` (сборки `8.3.27.1989`, `8.3.27.2214`) | `2.20` |
| `8.5.1` (сборка `8.5.1.1150`) | `2.21` |

Неизвестная версия отклоняется со списком известных. Если `--platform` не
указан, платформа берётся по порядку:

1. запись `[[database]]` для этой базы в `ibcmd-rs.toml`;
2. переменная `IBCMD_RS_PLATFORM`;
3. `platform` в `ibcmd-rs.toml`;
4. каталог утилиты `...\1cv8\<версия>\bin`; при загрузке — `version` в
   `Configuration.xml` дерева; при выгрузке режим совместимости 8.5 означает
   8.5.1;
5. иначе 8.3.27 с предупреждением.

При загрузке утилита проверяет, что формат дерева совпадает с платформой
базы, и отказывает до записи, если нет.

### Файл `ibcmd-rs.toml`

Читается рядом с утилитой, в `%APPDATA%\ibcmd-rs\` и в текущей папке (более
поздний побеждает) или один файл из переменной `IBCMD_RS_CONFIG`:

```toml
platform = "8.3.27.2214"        # для баз, которых нет в списке
db-server = "sql01"             # сервер по умолчанию
db-user = "reader"              # логин по умолчанию (пароль здесь не хранится)

[[database]]
name = "erp_prod"               # имя базы или маска со *
platform = "8.3.27.2214"

[[database]]
server = "sql02"                # необязательно: без него — любой сервер
name = "bsp_*"
platform = "8.5.1.1150"
```

Ошибка в файле или неизвестный ключ — отказ с путём и номером строки.

`ibcmd-rs settings show [--db-server <сервер>] [--db-name <база>]
[--config <файл>] [--platform <версия>] [--json]` показывает итоговые
значения и откуда взято каждое; пароль не печатается.

### Переменные окружения

| Переменная | Что задаёт |
|---|---|
| `IBCMD_RS_PLATFORM` | Платформа по умолчанию (`8.3.27`, `8.5.1`, сборка). |
| `IBCMD_RS_DB_SERVER` | Сервер SQL Server по умолчанию. |
| `IBCMD_RS_DB_USER` | Логин SQL Server по умолчанию. |
| `IBCMD_DB_PSW` | Пароль SQL Server. |
| `IBCMD_RS_CONFIG` | Путь к единственному файлу настроек вместо поиска `ibcmd-rs.toml`. |
| `IBCMD_RS_SQL_CONNECTIONS` | Число соединений с SQL Server (по умолчанию 4, не больше 64). |
| `IBCMD_RS_WORKERS` | Число потоков выгрузки (по умолчанию — число ядер, но не больше 16; явно — до 64). |
| `IBCMD_RS_VERBOSE=1` | Выгрузка в синтаксисе `ibcmd` печатает в stderr и свои служебные сводки (по умолчанию — только строки штатного `ibcmd`). |
| `IBCMD_RS_LEGACY_EXPORT=1` | Выгружать описания объектов прежними конвертерами (как до 0.2). |
| `IBCMD_RS_STAGE_TIMING=1` | Загрузка печатает время своих шагов, в том числе запросов к SQL Server. |

Порядок для подключения: параметр команды → файл `--settings` →
переменные окружения → `ibcmd-rs.toml` → раздел `database:` штатного
`--config` → значение по умолчанию. Пароль: `--db-pwd` или `-W` →
переменная `IBCMD_DB_PSW` (или названная в `--db-pwd-env`) → `--settings`
→ раздел `database:` штатного `--config`.

### Подключение к SQL Server

Утилита подключается к SQL Server сама, по протоколу TDS; `sqlcmd` и `bcp`
не нужны.

- **Сеть.** Только TCP. Для `np:` и `lpc:` укажите `--sqlcmd`.
- **Шифрование** включено, сертификат сервера принимается без проверки, как у
  `sqlcmd -C`.
- **Linux.** Вход Windows доступен только в Windows; в Linux нужен логин SQL
  Server.

## 3. Основные команды `ibcmd-rs`

Эти команды проверены на БСП и ERP УХ (платформы 8.3.27 и 8.5): результат
совпадает со штатной выгрузкой. Логин SQL Server у них задают `--sql-user`
и `--sql-pwd` (или переменная `IBCMD_DB_PSW`), сервер — `--server`.

### `mssql-dump-config` — выгрузка конфигурации

```
ibcmd-rs mssql-dump-config --database MyBase --extract-metadata-xml ^
  --extract-module-text --no-binary-rows -o C:\export\MyBase
```

| Параметр | Что задаёт |
|---|---|
| `--server <сервер>` | Сервер SQL Server (по умолчанию `localhost`). |
| `--database <база>` | База данных. |
| `--sql-user <логин>` | Логин SQL Server; без него — вход Windows. |
| `--sql-pwd <пароль>`, `--sql-pwd-env <имя>` | Пароль или переменная с ним (по умолчанию `IBCMD_DB_PSW`). |
| `-o, --output-dir <каталог>` | Каталог выгрузки. |
| `--overwrite` | Разрешить писать в непустой каталог. |
| `--extract-metadata-xml` | Выгрузить описания объектов в XML (нужно для полного дерева). |
| `--extract-module-text` | Выгрузить тексты модулей (нужно для полного дерева). |
| `--no-binary-rows` | Не сохранять сырые строки таблицы Config (быстрее). |
| `--platform <версия>` | Версия платформы, то есть формат XML. |
| `--include-config-save` | Выгружать и несохранённые изменения из ConfigSave. |
| `--file-name <имя>`, `--file-name-list <файл>` | Выгрузить только указанные строки Config (по `FileName`). |
| `--rows-dir <каталог>` | Читать строки Config из файлов `<FileName>__part<N>.bin` без сервера. |
| `--legacy-export` | Прежние конвертеры описаний объектов. |
| `--sqlcmd <путь>`, `--bcp-executable <путь>` | Работать через `sqlcmd` и `bcp`, как версия 0.2. |
| `--runtime-journal <файл>` | Журнал запросов к SQL Server в JSON (хэши запросов, без текста). |
| `--inflate`, `--require-complete-root-metadata`, `--require-complete-source-assets`, `--collect-all-source-asset-diagnostics` | Исследовательские: распаковка строк и строгие проверки выгрузки. |

Кроме дерева XML в каталоге появляется служебный `manifest.json`.

### `mssql-stage-source-objects` — загрузка конфигурации

```
ibcmd-rs mssql-stage-source-objects --database MyBase ^
  --source-root C:\export\MyBase --replace-config-save --allow-non-lab
```

После загрузки конфигурацию применяет штатный `ibcmd infobase config
apply`.

| Параметр | Что задаёт |
|---|---|
| `--server`, `--database`, `--sql-user`, `--sql-pwd`, `--sql-pwd-env` | Подключение, как у выгрузки. |
| `--source-root <каталог>` | Дерево XML. |
| `--replace-config-save` | Обязательное подтверждение: заменить содержимое ConfigSave. |
| `--allow-non-lab` | Обязательное подтверждение записи в базу. |
| `--base-free` | Загрузка в пустую базу: все строки собираются из XML, из базы ничего не читается. |
| `--verify` | Перед записью в ConfigSave выгрузить моделью получающуюся конфигурацию и сравнить каждый файл с деревом; расхождение отменяет загрузку, ConfigSave не меняется. Загрузка `infobase config import` делает это сама. |
| `--platform <версия>` | Версия платформы; формат дерева должен ей соответствовать. |
| `--path-prefix <путь>` | Загрузить только часть дерева (можно повторять). |
| `--script-only` | Только подготовить SQL-скрипты, ничего не записывая. |
| `--script-output <путь>` | Куда писать SQL-скрипты. |
| `--per-row` | Построчная загрузка вместо пакетной (быстрее для нескольких объектов). |
| `--bulk` | Пакетная загрузка (по умолчанию). |
| `--batch-size <n>` | Объектов в одном пакете SQL. |
| `--sqlcmd <путь>`, `--bcp-executable <путь>` | Работать через `sqlcmd` и `bcp`, как версия 0.2. |

### `source-diff` — сравнение двух деревьев XML

```
ibcmd-rs source-diff -o diff.json C:\export\native C:\export\ours
```

Сравнивает файлы двух деревьев по пути и содержимому. В отчёте — итоги
(`unchanged`, `different`, `left_only`, `right_only`) и список расхождений.
`--path-prefix <путь>` ограничивает сравнение частью дерева; без `-o`
отчёт печатается в stdout.

### `settings show` — итоговые настройки

Печатает, какие сервер, логин, платформу возьмёт команда для базы и откуда
взято каждое значение. Параметры: `--db-server`, `--db-name`, `--config`,
`--platform`, `--json`. См. [раздел 2](#файл-ibcmd-rstoml).

### `compatibility` — таблица возможностей

Печатает в JSON, какие операции реализованы и для каких форматов и версий
(`-o <файл>` — записать в файл).

## 4. Остальные команды

Исследовательские и лабораторные команды: ими получены и проверены
результаты проекта, но проверены они меньше основных, а часть требует
особых условий (отдельные базы, `bcp.exe`, трассировку). Параметры каждой —
`ibcmd-rs <команда> --help`.

Команды, которые пишут в базу, требуют подтверждений `--replace-config-save`
и `--allow-non-lab`. Запускайте их только на копиях баз.

### Файлы CF и конвертация

| Команда | Что делает |
|---|---|
| `cf inspect` | Краткая опись содержимого архива CF в JSON. |
| `cf verify` | Проверка структуры CF, выбранных частей и контрольных сумм SHA-256. |
| `cf extract` | Извлечь один элемент хранилища CF в отдельный каталог. |
| `cf export` | Выгрузить распознанные записи CF в дерево XML без платформы. |
| `cf overlay` | Наложить выбранные файлы XML на базовый CF и собрать новый CF. |
| `cf bootstrap` | Собрать новый CF из полного дерева XML без базы и платформы. |
| `convert` | Конвертация целиком: XML ↔ CF между указанными профилями версий (`--source-format`, `--target-format`, `--source-profile`, `--target-profile`). |

### Загрузка отдельных объектов

`settings-storage`, `functional-option`, `functional-options-parameter`,
`event-subscription`, `scheduled-job`, `http-service`, `web-service`,
`ws-reference`, `xdtopackage`, `integration-service`, `language`, `style`,
