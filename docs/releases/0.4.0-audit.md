## Accepted boundaries

S1 is an explicit allowlist; unsupported combinations and borrowed extension
objects refuse before writing. The total rebuilt-table budget is enforced before
publication. ERP UH measurements use a configuration-only backup with empty
application tables; they demonstrate schema behavior, not migration of large
production data. The `c4629235` ordering approximation is retained only with the
native-session and export proof documented in the cache evidence.

The `.ui` platform licensing records stay untouched. Creation, dynamic live
updates and broader restructuring remain outside the 0.4 implementation scope;
related research and 0.5 branches are preserved.

## Integrated release validation

All three tracks passed independent review. Integrated library tests: 3598 passed, 0 failed, 9 intentionally ignored. Required GitHub contexts are configured with the verified GitHub Actions application identity; force pushes and deletion of master are disabled.

All 16 local gates passed. The final integrated binary passed all eight DB/offline
exports and all four fresh-empty-database import -> native apply -> native export
cycles, with complete inventory and ConfigDumpInfo comparisons:
[final measurements and boundaries](evidence/0.4.0/README.md).

Both required offline matrices and all other PR checks passed on the integrated
candidate. The [release dry run](https://github.com/Untru/ibcmd-rs/actions/runs/36815209249)
passed Gate and both target builds; all six downloaded artifacts were independently
audited. Final merge/master and tag-run states are recorded by
[GitHub Actions](https://github.com/Untru/ibcmd-rs/actions), rather than asserted in
this pre-tag source document.

All 31 functional issues are closed with verified evidence. The remaining
automatic-publication part of #333 stays open until a real v0.4.0 tag succeeds.
Before tagging, it must be explicitly moved to a later milestone with the
dependency reason recorded on the issue, as permitted by the release policy.
It will then be closed with the run and
published asset evidence and returned to the historical 0.4 milestone. No tag may
be created until milestone statuses are current and the pre-tag policy in
`docs/release-criteria.md` is satisfied.
